# ADR-002 — Home override and user control

- Date: 2026-10-09
- Status: proposed; not signed off
- Firefox candidate: chrome_settings_overrides.homepage references bundled newtab.html, sharing the React app. MDN describes relative bundled paths and most-recent-extension precedence. Generated-path/build validation passes; owner reported Home rendering in development. Regular-install consent/control/restoration remain unverified.
- Chrome: no Home override declared in the current candidate manifest. Manual Settings → Appearance → Show Home button guidance is provided, conditional on browser acceptance of the local extension URL. This fallback has NOT been runtime verified.
- User control: no runtime Home toggle. Firefox Settings → Home controls the override; app makes no claim that declared override means user consent or active Home control.
- Evidence: Both target builds and New Tab smoke pass; see final-results.json and browser smoke JSON/screenshots. Temporary/unpacked headless installations do not prove regular-install consent, Home conflict or restoration. See P00_REPORT and browser checklist.
- Open gates: regular installation consent, browser controls, other-extension precedence, uninstall restoration and Chrome Home platform/store certification. Generated bundled path and Firefox no-data-transmission declaration pass manifest audit.
- Privacy/scope: local page only; Home remains an MVP target. No remote redirect or personal data transmission.
- References: https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/manifest.json/chrome_settings_overrides ; https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/manifest.json/chrome_url_overrides
- Approval: evidence and owner sign-off required; no scope downgrade accepted.
